7. **RESOLVED: `fig3_04_paired_trajectory_corrected.png`'s "7 folds" label was a real bug in `make_figures.py`, not a genuine 7-fold analysis.** `Source/logs/log05_log11_grouped_cv_verification.csv`'s `log05_baseline_grouped_cv` block has 7 rows, not 5 — the `fold` column literally contains the strings `"mean"` (0.7270) and `"sd"` (0.0208) as two extra pseudo-rows alongside real folds 1-5. The original plotting code filtered only on `item == "..." and r["baseline_acc"]`, which didn't exclude those two rows, so it averaged in all 7 "baseline_acc" values — including treating the **SD value (0.0208) as if it were a 7th fold's accuracy**. `mean([0.6944, 0.7222, 0.7500, 0.7361, 0.7324, 0.7270, 0.0208]) = 0.6261`, which is exactly the erroneous ~0.625 marker that sat below all the real fold points (~0.68-0.80) on the chart. It's genuinely 5-fold CV, matching every other analysis in this project. **Fix applied:** `Source/make_figures.py` now filters on `r["fold"].isdigit`, giving the correct 5-fold mean of 0.7270 (matching the CSV's own precomputed `mean` row exactly). Figure regenerated and replaced in this export.
