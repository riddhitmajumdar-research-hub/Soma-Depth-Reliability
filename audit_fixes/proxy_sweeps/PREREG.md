# PREREG: proxy sweeps on eight networks

This protocol was written before any result of these sweeps. Quotations are from the earlier text (sections in brackets). Decisions D1 to D10 were fixed before any result.

## 1. Question
How far does the certified depth floor move when the build-time choices of Table 1 are changed, and does mixed-depth training narrow the spread of floors that clean-only training shows, when each is measured on eight retrained networks (seeds 101 to 108) with scripts and per-seed results archived in the repository? The values in the record's Table 1 and in its eight-network rerun have no result file in the repository; these sweeps produce archived values to replace them or to show that they differ.

## 3. Seeds and hardware
Seeds 101, 102, 103, 104, 105, 106, 107, 108 (**D10**). Not changed after any result.

Hardware (updated before any result): the sweeps run on the owner's Mac (Apple M4, 10 cores), one process per seed with one thread per process, because no remote machine is available. This changes execution only. Platform differences from the Linux container of the robustness battery are known (Log 28: baseline floors differed by 0, -0.5, -1.37 and +0.5 cm for seeds 101 to 104, battery minus local replicate); the consistency checks report them.

## 4. Pipeline (unchanged from the certified sweep and the robustness battery)
- Training data: mixed-depth degraded windows at training depths 0, 3, 6, 9 and 12 cm, 25 windows per class per depth, 27.05 dB (`Source/degradation_aware_final_sweep.py`), generated with the condition's changed parameter. Clean-only arm: `Source/cnn_classifier.build_raw_dataset`.
- Evaluation grid: the 23 depths of the certified sweep ([III.E] "12 evenly spaced from 0 to 15 cm plus 11 added between 3.5 and 8 cm"); 300 windows per depth (100 per class), generated with the condition's changed parameter (clean-only arm: the baseline degradation).
- Null: 200 shuffled-label controls per network; p = (number of controls with accuracy at or above the real network + 1) / 201; smallest p = 1/201 = 0.00498.
- Correction: Benjamini-Hochberg at 0.05 over the 23 depths of each (seed, condition).
- Floor: the first depth that is not significant ("The floor is the first depth that fails"). If every depth is significant the floor is recorded as 15.0 cm, the fallback cap, and marked censored (a lower bound).
- Noise: 27.05 dB, sigma = 10^(-SNR/20), in training and evaluation.
- Evaluation draw: deterministic per (seed, condition) (crc32 of the condition id); all models of a seed and condition are scored on the same windows.

## 5. Control policy (D1)
Each changed parameter is applied in both training and evaluation. For every condition and every seed the real model and its 200 controls are retrained: the controls are trained on shuffled labels of that condition's training data, for the same number of epochs as the real model. Nothing is reused between conditions. This follows the record's wording ("the real model and 200 controls retrained each time") and replaces the robustness battery's policy of one set of controls per seed for all conditions. The baseline training set equals the certified sweep's (checked: identical arrays for the same seed).

## 6. What will be reported
Per condition: the eight per-seed floors, their mean, SD (n - 1), median, the number of censored seeds (floor = 15.0 cm with every depth significant) and the number of seeds at 0.00 cm (`summarize_proxy.py`). For clean-only against mixed-depth (**D7**): the primary test is the Wilcoxon rank-sum (Mann-Whitney U) test, two-sided, unpaired, of the eight `7_clean_only` floors against the eight `0_baseline` floors; the secondary test is the paired signed-rank test over seeds. Both are declared before any result. All values are proxy floors, not certified. Files, one set per seed so that parallel processes never write the same file: `proxy_floors_<seed>.csv`, `proxy_depth_detail_<seed>.csv`, `proxy_run_<seed>.log` in `audit_fixes/cloud/proxy_sweeps/results/`.

**Consistency checks (declared before any result; reported, never used to adjust anything).** After the tests, `summarize_proxy.py` reports: (a) the eight `0_baseline` floors against condition `1_baseline` of the robustness battery (`audit_fixes/cloud/battery/results/floors_101-104.csv` and `floors_105-108.csv`), seeds 101 to 108: per-seed difference, mean and SD of the differences, correlation; (b) the same floors against `naive_floor_cm` of `Source/logs/degradation_aware_final_results.csv`, seeds 101 to 108; (c) the eight `7_clean_only` floors against `agg_floor_cm` of `audit_fixes/lane5/clean_trained_sweep/clean_sweep/logs/lane5_clean_per_class_results.csv`, seeds 101 to 108. Control draws and platform differ from those runs, so identical floors are not expected.

## 7. Commitments
No threshold (0.05, 200 controls, 15.0 cm cap, 23-depth grid), no seed, no condition and no test is changed after any result is seen. A condition that cannot run is recorded as skipped, not substituted. Every deviation from this file is recorded in the run log and in the report.
